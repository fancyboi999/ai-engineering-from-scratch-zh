# 审计与遥测字段简报

这是一份面向 MCPA“安全与治理”领域可审计性目标的一页式参考资料：设计可审计性与可观测性，使协议活动能够被追踪、归因和复核。内容与 MCP 2026-07-28 对齐。

## traceparent 字段布局

`traceparent` 由四个连字符分隔的小写十六进制分段组成，长度固定。它携带在 `_meta` 中，是反向 DNS 前缀规则的唯一例外（SEP-414）：

| 分段 | 长度 | 含义 |
|---------|--------|---------|
| version | 2 个十六进制字符 | 格式版本，当前使用 `00` |
| trace id | 32 个十六进制字符 | 标识完整操作；每一跳都保持不变 |
| parent id | 16 个十六进制字符 | 标识一个 span；每一跳都会生成新值 |
| flags | 2 个十六进制字符 | 位 flags，例如 trace 是否采样 |

全零的 trace id 或 parent id 无效，必须拒绝。`tracestate`（供应商状态）和 `baggage`（用户自定义上下文）是与 `traceparent` 一同传播的独立 `_meta` 键；本课服务器会在每一跳原样转发二者。

## 派生子 span

调用其他服务前，保留 trace id，并生成新的 parent id：

```python
def child_traceparent(value):
    parsed = parse_traceparent(value)
    return make_traceparent(parsed["trace_id"], new_span_id(), sampled=parsed["flags"] != "00")
```

## 审计条目的五类字段

| 字段 | 来源 | 绝不能使用 |
|-------|--------|-----------|
| 谁 | 有效凭据解析出的已认证 principal | `clientInfo.name`（自行报告，只供展示） |
| 做了什么 | Method、工具名、已脱敏标记字段的参数 | 未脱敏的原始参数值 |
| 何时 | 写入条目时取得的时间戳 | 客户端提供的时间声明 |
| 结果通道 | complete、isError 或 protocol_error，以调用实际终结方式为准 | 把所有结果折叠成一个笼统状态 |
| 关联 | Request id（本跳）加 trace id（完整操作） | 跨服务边界只使用 request id |

## 脱敏规则

工具注册时附带一组标记参数字段名。创建条目前，把每个标记字段的值替换为固定标记。替换发生在条目写入及计算哈希之前，因此原始值从未出现在持久记录、备份或哈希计算中。工具处理器仍能收到真实值；只有审计轨迹中的副本被脱敏。每台服务器独立地把自己的脱敏策略应用到自己的日志。

## 哈希链验证步骤

1. 以 genesis 值作为预期的前一哈希。
2. 按顺序处理每个条目：确认其存储的 `prev_hash` 等于预期前一哈希；根据条目自身存储的字段重算摘要，并确认与其存储的 `hash` 匹配；然后把预期前一哈希设为该条目的 `hash`，继续处理。
3. 干净的链会检查完所有条目。遭篡改的链会在第一个“存储哈希与内容不匹配”的条目停止；如果攻击者也修补了该条目自身的哈希，则会在紧接着的条目停止，因为后者的 `prev_hash` 仍指向原始值。

这是篡改证据，不是篡改预防：底层存储仍可能被写入，但若不按顺序重写其后的每个条目，就无法让修改隐形。

## 为什么 clientInfo 绝不能代表“谁”

`clientInfo` 和 `serverInfo` 都由发送方自行报告，协议不会验证。规范明确要求实现不得依赖它们做安全决策。若审计记录把 `clientInfo.name` 用作“谁”，任何调用方都能自行选择问责日志中的名字，使记录在写入前就失去意义。

## 跨越一跳进行关联

同一次操作中的两台服务器维护两条独立哈希链。它们不共享日志，同一操作在不同服务器上的 request id 也无需相同；每一跳都会生成自己的 id。跳两侧唯一保证相同的值是 trace id，因此审核者或 tracing 后端应以它为连接键，重建一次操作经过所有服务的完整路径。
