# 工具调用生命周期状态图

这是一份针对 MCPA“交互与执行”领域的一页式参考，与 MCP 2026-07-28 对齐。编写生命周期或错误处理代码时，可放在客户端或服务器实现旁随时查阅。

## 八个检查点

| 检查点 | 是否在线路上 | 决定什么 | 如何结束 |
|---|---|---|---|
| 发现 | 是，`server/discover`（可缓存） | 服务器提供哪些版本和能力 | 客户端版本不受支持时返回 `-32022` |
| 列出 | 是，`tools/list`（可缓存，顺序确定） | 存在哪些工具、schema 和注解 | 没有工具特有的结束方式；返回稳定列表 |
| 选择 | 否 | 模型根据已有上下文选择哪个工具 | 不适用；完全发生在宿主内部 |
| 确认 | 否 | 调用发出前，人类是否批准 | 如果拒绝，生命周期直接在这里结束 |
| 调用 | 是，`tools/call` | 请求真正离开客户端 | 暂无结果；这里只会启动下一个检查点 |
| 验证 | 不发送新消息；控制响应走向 | 服务器是否暴露了该名称的工具 | 未知工具返回协议错误 `-32602`，不会继续执行，也不会产生结果 |
| 执行 | 不发送新消息；控制响应走向 | 参数是否符合 schema，处理器是否成功 | 输入错误或业务失败返回 `isError` 结果；只有真正的意外故障才返回 `-32603` |
| 结果 | 是，作为 `tools/call` 的响应 | `resultType` 是 `complete` 还是 `input_required` | `input_required` 回到调用；`complete` 为最终结果 |

## 两条错误通道

| 通道 | 形式 | 用途 | 模型能否自行修正 |
|---|---|---|---|
| 协议错误 | JSON-RPC `error` | 未知工具（`-32602`）、格式错误的请求、真正的服务器故障（`-32603`） | 不能，因此客户端不应盲目重试 |
| 工具执行错误 | 完整结果，`isError: true` | 错误参数、上游 API 失败、业务规则违规 | 能，这条通道就是为此设计的 |

经验法则：验证阶段只会产生协议错误。执行阶段几乎总是产生工具执行错误；只有当失败无法通过调用方输入避免时，才使用协议错误。

## 暂停、取消和重发

| 情况 | 会发生什么 | 调用方怎么做 |
|---|---|---|
| `resultType: "input_required"` | 服务器需要更多输入；响应包含 `inputRequests`、`requestState` 或两者 | 使用新的 JSON-RPC id 重试，提供键名匹配的 `inputResponses`，并原样回传 `requestState` |
| 硬超时 | 本次尝试不会产生任何 resultType | Streamable HTTP：关闭请求流。stdio：发送 `notifications/cancelled`，包含 `requestId` 和可选原因 |
| 流中断 | 请求和结果都丢失；这里没有可恢复机制 | 使用新 id 重发；重复有副作用的调用前，把 `idempotentHint` 当作提示，而不是保证 |
| 取消后的迟到响应 | 已经放弃的 id 仍收到结果或错误 | 忽略它 |

## 发布 tools/call 路径前的检查清单

- 未知工具名称始终返回 `-32602`，绝不是 `-32601`。
- 参数 schema 失败和业务规则失败返回 `isError: true` 结果，绝不返回 JSON-RPC 错误。
- 每个请求（包括重试）都通过 `_meta` 携带协议版本和客户端能力。
- `input_required` 之后的每次重试都使用新 id，并逐字节原样回传 `requestState`。
- 流中断后的每次重发都使用新 id；有副作用的工具应返回明确、不透明的句柄，让重发可以基于已有状态操作，而不是猜测。
- 超时具有硬上限，即使进度通知不断到达，也不会延长。
- stdio 上的取消是通知，绝不是等待响应的请求。
