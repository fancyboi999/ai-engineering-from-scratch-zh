# MCPA 蓝图是学习预算，不是核对清单

> 考试大纲列出可能考什么，蓝图则说明各部分实际占多少。应把 MCPA 蓝图当作学习时间的预算依据，而不是浏览一次就丢到脑后的目录。

**类型：** Learn
**语言：** Python
**前置要求：** 无
**预计时间：** 约 45 分钟

## 学习目标

- 说出 MCPA 的五个领域及其准确的官方权重，并确认总和为 100%
- 根据领域权重，按比例分配固定的学习时间预算
- 说明 MCPA 考试的形式、费用、有效期和重考政策，并解释认证页面所写的 90 分钟与发布新闻稿所写的 120 分钟为何冲突
- 解释为什么官方没有公布考试题数和及格分数，以及这会如何影响考生评估备考程度
- 识别题目中的旧版协议干扰项，例如 `initialize` 握手、会话，以及对未知工具使用 `-32601`，并根据 2026-07-28 版本判断正确答案
- 梳理从本导读到综合项目的 34 课路线，并说明每课对应哪个领域

## 问题背景

Model Context Protocol 涉及的范围很广：角色与消息、schema、传输、工具与资源生命周期、sampling、错误处理、OAuth、同意、审计能力，以及围绕协议发展起来的生态。如果考生打开 MCPA 指南后从头读到尾，在每个主题上投入差不多的时间，就等于在不知不觉中做了一个假设：考试大纲的每一部分同样重要。事实并非如此。定义这项考试的认证页面还公布了一份蓝图，把内容分成五个领域，并为每个领域标出百分比权重。这个数字不是装饰。它说明考试内容平均如何分布，是考试前官方能提供的最接近“答案提示”的信息。

忽视蓝图是一种规划错误，就像构建一个永不失效的缓存：开始时看不出问题，直到错误假设与现实之间的偏差带来代价。若把时间平均分给五个领域，你必然会低估占考试 26% 的领域，同时在仅占 14% 的领域投入过多。差距还会叠加，因为“交互与执行”和“安全与治理”两个领域合计占蓝图的一半。不参考权重的学习计划，会把一个权重几乎是另一个两倍的领域当成同等重要。

还有第三个问题，它浪费的不是时间，而是分数。每道 MCPA 题目都以 2026-07-28 版本为准，但考生对 MCP 的直觉往往来自旧教程、博客文章，甚至来自本课程修正前的早期草稿。那些资料描述的是另一套协议：每条连接先执行 `initialize` 握手，并在会话中保存状态。描述旧协议的选项读起来很熟悉，甚至显得很权威；正是这种熟悉感，让它成为很有迷惑性的错误答案。若不能一眼分辨旧版认知与 2026-07-28 的事实，就会被“听起来没错、实际版本不对”的选项骗走分数。最后，一套 34 课的课程很容易让人顺序读完，却始终没意识到每课在训练五个领域中的哪一个。本课要在你继续学习前解决这四个问题：把官方权重转换成明确的时间预算；建立一种诚实反映官方已知与未知信息的备考评估方式；训练识别旧版协议干扰项的反射；给出覆盖五个领域的完整 34 课路线。

## 核心概念

先看数字，因为它们是整个计划的基础。MCPA 蓝图公布了五个领域：MCP 基础占 16%，架构与组件占 14%，交互与执行占 26%，安全与治理占 24%，用例与生态占 20%。相加正好是 100%。这个总和值得亲自核对，而不是直接相信摘要，因为蓝图若合计不为 100%，通常意味着转录出了错。每个领域还公布了具体的子能力。MCP 基础包括目的与范围、核心概念、互操作性与价值；架构与组件包括 schema 与结构化数据、host/client/server 角色和模型交互流程；权重最高的交互与执行包括交互模式与响应处理、错误处理、工具调用生命周期和协议原语；安全与治理包括信任边界、权限与同意、风险与安全控制、审计能力与可观测性；用例与生态包括角色与采用、实际用例、生态与可移植性。本段所有事实及其来源和检索日期都记录在仓库的 `certifications/mcpa/research/source-verification-ledger.md`，你可以自行核验，不必只相信课程正文。

接着看蓝图之外的考试机制。考试采用在线监考和选择题形式，内容对应 2026-07-28 版 Model Context Protocol 规范，整套课程也以该版本为准。单独报名考试的费用是 250 美元，不包含任何捆绑订阅。证书有效期为两年，首次未通过的考生可免费重考一次。就连考试时长也没有唯一说法：认证页面写的是 90 分钟，Linux Foundation 自己的发布新闻稿却写 120 分钟。本课程以更直接面向考试的认证页面为准，同时把新闻稿的数字记录为尚未解决的差异，而不是悄悄挑一个更顺眼的数字；`certifications/mcpa/research/source-verification-ledger.md` 保留了两个数字及其来源，依赖这些信息前应重新核验。还有两个数字在两处官方来源中都没有出现：准确题数和及格分数。不要用猜测填补空白，应把“未公布”本身视为事实。这意味着你不能把备考目标设成“60 题至少答对 N 题”，而应追求五个领域都达到扎实且均衡的掌握程度，因为公开信息只支持这种目标。

现在把数字变成计划。既然蓝图权重表示考试内容占比，把相同比例应用到学习时间预算，就能得到合理的分领域目标：某领域的学习时间等于总时间乘以该领域权重，再除以 100。这就是普通的按比例分配，与预算科目或投资组合的配置算法相同，而且是确定性的：预算和蓝图相同，结果就相同。计划的另一半是衡量当前水平。若只对五个领域的练习正确率取平均，就会把占 14% 的领域与占 26% 的领域等量看待，让轻权重领域的优势掩盖重权重领域的薄弱。加权备考程度会先把每个领域的练习正确率乘以蓝图权重再求和，因此结果与考试重点一致，而不是简单五等分。时间预算和加权备考程度都由 `code/main.py` 中简短且确定性的函数实现；下图把五项权重可视化，便于和你自己的分配比较。

### 读题方法：识别旧版协议干扰项

好的干扰项不是随机噪声。MCPA 考试以 2026-07-28 为准，但 MCP 已经历五次修订，首个 2024-11-05 版本的认知仍随处可见：旧博客、缓存文档，以及本课程修正前的早期草稿里都有。这套旧认知读起来流畅且笃定，所以作为错误答案尤其危险。不要只保持模糊的警惕，而要训练明确的检查动作。第一，看到选项声称首次真实请求前需要设置步骤、握手或协商，应立即核对版本：2026-07-28 没有这些步骤，每个请求都在 `_meta` 中携带自己的协议版本和能力，因此 `initialize` 调用或“连接先协商版本”的说法都属于旧版特征。第二，看到选项用会话或粘性连接解释服务器如何跨调用记住状态，也要警惕：2026-07-28 是无状态协议，跨请求状态通过服务器生成的显式 handle 传递，并作为普通参数回传，而不是藏在隐式会话中。第三，核对错误码的真实含义：未知工具应返回 `-32602`，不是很容易混淆的 `-32601`；后者只表示未知方法。工具参数不符合 schema 也不是协议错误，而是带有 `isError: true` 的普通结果，模型可以读懂并修正。`certifications/mcpa/research/mcp-2026-07-28-brief.md` 第 16 节持续维护这些陷阱，把每条错误旧认知与取代它的 2026-07-28 事实并列。第一次做练习题前读一遍，考试前一晚再读一遍。

### 路线：34 课覆盖五个领域

本路线共 34 课，编号 00 至 33，每课至少对应蓝图中的一个领域。大多数课程只属于一个领域，例如工具原语属于交互与执行，OAuth 属于安全与治理。少数课程确实位于交叉点，因此同时标记两个领域。例如 JSON-RPC 与 Meta 同时属于基础和架构，因为它讲解的消息信封既是核心概念，也是考试会单独考查的架构组成；传输与 HTTP 标头同理，同时属于交互和架构——同一个机制可以从两个考试角度提问。路线最后的第 33 课综合项目刻意标记全部五个领域，因为它要求在一次完整交互记录中运用每个领域的概念。本课的 `code/main.py` 把整条路线编码为数据，而不是只写在正文里，因此脚本或学习者都能准确查询“哪些课程训练安全与治理”，无需凭记忆猜测。

## 交互实验

运行下面的脚本。它会验证领域权重和 34 课路线，然后严格按两个官方来源打印考试事实，包括 90 分钟与 120 分钟的时长冲突，以及两个故意设为 `null` 的字段——因为两个来源都没有公布这些信息。脚本还会把 40 小时示例预算分配给五个领域，打印基于示例练习分数的备考程度，并给出同一组分数的简单平均值，让你直接看到二者的差异。最后，它会打印路线总长度，以及 `route_for_domain` 为两个示例领域返回的 lesson slug，也就是上文路线部分用文字回答的问题。

```bash
python3 code/main.py
```

把打印出的分配表与上图对照。最高的两根柱，即交互与执行、安全与治理，也应该对应分配表中最大的两个数字，因为二者来自同一组权重。修改 `demo()` 传给 `allocate_study_hours` 的 `total_hours` 后重新运行，表中每个数字都会变化，但领域之间的比例保持不变，因为分配依据是相对权重，而不是某个特定预算。还可以在课程目录的 Python shell 中调用 `main.route_for_domain("not-a-real-domain")`，观察它拒绝非法请求，而不是悄悄返回空路线。

## 实践实验

打开下一课前，用自己的数据完成三件事，不要沿用演示里的示例。第一，确定从现在到考试日期实际可用的小时数，用该数字调用 `allocate_study_hours`，把五个领域的目标写在之后能持续看到的地方，例如下方交付的速查表。第二，做本路线的练习题或诊断评估时，为每个领域持续记录 `(答对数, 总题数)`，并定期用这些数据调用 `estimate_readiness`。特别观察从未练习过的领域开始有数据时，结果如何变化：未练习领域在估算中按零分计算，而不会被悄悄排除。第三，找出备考程度最低的领域，对它调用 `route_for_domain`，下一步按返回的精确课程列表依次学习，不要习惯性地继续顺着编号往下读。每周重复这三项检查。只制定一次而从不更新的计划，不是计划，只是一张快照。

## 验证

运行 `python3 -m unittest discover code/tests`。测试会检查：五个领域权重之和是否恰好为 100，验证器是否拒绝总和不为 100 的权重；学习时间是否按准确比例分配，且分配结果之和是否回到原预算；加权备考程度是否让重权重领域的掌握比轻权重领域产生更大影响，而不是把所有领域视为相同；零小时预算是否无需特殊处理就为每个领域分配零；没有做题记录的领域是否贡献零分而不是触发除零错误；备考程度和路线查询是否都会拒绝未知领域，而不是静默失败；路线是否覆盖编号 00 至 33 的全部 34 课，且只有综合项目横跨所有领域。若其中任何测试失败，说明代码与课程正文已经偏离；计算逻辑以代码为准。

## 综合项目关联

刚才运行的 `estimate_readiness` 不是一次性演示。第 33 课的综合备考评审会再次使用同一套加权评分模型，但届时输入的是你真实的诊断或模拟考试领域分布，用来判断是否确实可以预约考试，或某个领域是否还需要再学一轮。请保留本课的速查表、两个学习函数和路线表。接下来的 34 课都至少对应这里列出的五个加权领域之一；到了综合项目，你要用自己的数据重新执行同一套计算，证明学习覆盖符合蓝图，而不是仅仅符合阅读顺序。

## 关键术语

| 术语 | 含义 |
|------|------|
| 蓝图 | 官方公布的五个 MCPA 领域及其百分比权重表 |
| 领域权重 | 某一领域平均占考试内容的百分比 |
| 学习时间预算 | 考试前可用的固定小时数，按领域权重分配 |
| 备考程度估算 | 使用蓝图权重而不是简单平均值，对各领域练习正确率求加权平均 |
| 未公布信息 | 题数或及格分数等两个官方来源都没有说明的考试细节 |
| 旧版协议干扰项 | 描述 2026-07-28 之前 MCP 行为的错误选项，例如 `initialize` 握手或会话 |
| 路线 | 34 课分别对应一个或多个训练领域的映射 |
