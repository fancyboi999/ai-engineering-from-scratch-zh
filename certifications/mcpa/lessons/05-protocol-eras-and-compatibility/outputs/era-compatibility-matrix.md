# 协议时代兼容性矩阵

面向 MCPA「MCP Fundamentals」领域、与 MCP 2026-07-28 对齐的一页式参考资料。

## 修订时间线

| 修订版 | 时代 | 主要变化 |
|---|---|---|
| 2024-11-05 | 旧版 | 首个公开修订版：提供 stdio 和 HTTP+SSE 传输，以及每次连接开始时执行的旧版握手。 |
| 2025-03-26 | 旧版 | Streamable HTTP 取代 HTTP+SSE；加入 OAuth 2.1 授权、工具注解和音频内容。 |
| 2025-06-18 | 旧版 | 加入结构化工具输出、资源链接、elicitation、OAuth 资源服务端分类和 MCP-Protocol-Version 标头；移除 JSON-RPC 批处理。 |
| 2025-11-25 | 旧版 | 加入图标、增量 scope 同意、工具命名指导、URL 模式 elicitation 和实验性 task；验证错误改为工具执行错误。 |
| 2026-07-28 | 现代 | 采用无状态核心，取消握手和会话；加入 server/discover、Multi Round-Trip Requests、resultType 和 subscriptions/listen；将 task 移至扩展；弃用 roots、sampling、logging 和 Dynamic Client Registration。 |

## 术语

- **现代**：2026-07-28 及后续版本。版本、身份和能力通过逐请求元数据传递。
- **旧版**：2025-11-25 及之前版本。连接通过握手打开，并创建会话。
- **双时代**：同时支持两个时代，并在解析前明确判断时代的实现。

## stdio 探测

在发送任何其他请求前先发送 `server/discover`，并在 `_meta` 中携带客户端首选版本：

1. 返回 `DiscoverResult`：服务端属于现代时代。使用 `supportedVersions` 中的版本。
2. 返回可识别的现代错误（例如错误码 -32022 的 `UnsupportedProtocolVersionError`）：服务端属于现代时代，但要求其他版本。使用 `data.supported` 中的版本重试，不要回退。
3. 返回其他错误，或在合理超时时间内没有响应：服务端属于旧版。回退到旧版握手。

绝不要将回退绑定某个特定错误码：无法识别的错误与超时表达的是同一结论。

## HTTP 探测

先尝试现代请求。收到 `400 Bad Request` 时，必须先读取正文再作判断：

- 正文包含可识别的现代 JSON-RPC 错误：服务端属于现代时代。重试或修正请求，不要回退。
- 正文为空，或不是可识别的现代错误：服务端属于旧版。回退到旧版握手，必要时再回退到已弃用的 HTTP+SSE 传输。

## 兼容性矩阵

| 客户端 | 服务端 | 结果 |
|---|---|---|
| 现代 | 现代 | 可以工作。server/discover 可选；版本不匹配时会出现 UnsupportedProtocolVersionError，客户端随后使用双方共同支持的版本重试。 |
| 现代 | 旧版 | 失败。旧版服务端无法读取逐请求元数据；若客户端支持双时代探测，本可在重要请求发出前发现问题。 |
| 双时代 | 现代 | 可以工作。探测返回 DiscoverResult 或可识别的现代错误，因此客户端继续使用现代路径。 |
| 双时代 | 旧版 | 可以工作。探测返回无法识别的错误或超时，因此客户端回退到旧版握手。 |
| 旧版 | 现代 | 失败。旧版客户端的开场请求是现代服务端未实现的方法，而且缺少现代服务端要求的元数据。 |
| 旧版 | 双时代 | 可以工作。服务端响应旧版握手，并按协商好的旧修订版为该客户端提供服务。 |
| 旧版 | 旧版 | 可以工作，完全遵循旧修订版自身的规则。 |

## 考试要点

- 2026-07-28 没有握手和会话；每个请求都能自我描述。
- 时代判断是服务端的属性，应按进程（stdio）或 origin（HTTP）缓存；判断后来失效时可以重新探测。
- 现代专用服务端拒绝旧连接尝试时，仍应列出自己支持的版本，因为旧版专用客户端没有其他途径获知可用版本。
- 可识别的现代错误绝不会触发旧版回退。只有无法识别的错误或超时才会触发。
