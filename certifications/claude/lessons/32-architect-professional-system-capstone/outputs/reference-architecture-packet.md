# 参考架构包：区域支持解决方案

## 1. 管理层决策

批准为期六周、仅英语、人工审核的试点。支持运营拥有结果：将符合政策的首响时间从 11 分钟降至 3 分钟以内。不自动退款或删除账户；财务保留退款权限。安全、隐私和区域数据负责人批准各自边界。

## 2. 发现

系统分类账单和配送工单、检索现行区域政策、只读取已分配账户、起草回复并建议而不执行操作。质量目标为至少 98% 的草稿有来源支持，P95 目标为 8 秒。非目标包括自主发送、员工排名、关闭账户和试点之外的语言。

## 3. 架构决策

选择确定性的接收、检索、起草、验证和审核工作流。否决单次增强调用，因为来源和故障会被压扁；否决自适应 agent，因为常规路径已知，且没有测量收益足以证明可变工具选择合理。若超过 20% 被接受工单需要安全的未建模发现，则重新考虑。

## 4. 系统与数据视图

经认证的接收层验证工单和区域；按元数据过滤的检索返回现行政策 ID；有边界的起草步骤接收最小化账户事实。进入审核队列前运行 schema、语义、来源和策略校验器。每条边携带主体、租户、schema 版本、超时、错误类别、追踪 ID 和负责人。部分证据不产生操作建议。

## 5. RAG 与知识

政策运营拥有带版本来源。感知标题的分块保留规则、例外、区域、生效日期、权限和访问元数据。混合检索在排序前过滤；经验证索引原子激活，前一索引保留作回滚。检索门禁覆盖召回、新鲜度、冲突、过期版本、未授权来源和对抗内容。

## 6. 集成与身份

直接类型化服务调用适合首个单宿主试点。每次调用传播可信主体和租户声明。工具拆分为政策读取、已分配账户读取和草稿存储；不包含退款执行。未来执行器需要精确主体、账户、金额、原因、过期、单次使用、幂等性和系统记录对账。

## 7. 评估与可观测性

golden set 对普通、模糊、过期、冲突、未授权、对抗、区域和高风险案例分层。发布要求 100% 硬控制通过、至少 98% 政策支持、P95 低于 8 秒、无高风险回归且每份被接受草稿成本在预算内。追踪连接检索、工具、验证、审核和结果，不存储凭证。

## 8. 治理

风险登记册覆盖过期政策、跨租户访问、prompt 注入、无支持退款、不公平的语言表现和审核人超载。每项控制都有负责人、测试、证据、失败响应和审核触发条件。合格审核人先获得来源证据和带原因编码的操作。法律、隐私、安全、财务和领域负责人决定其义务。

## 9. 运维与移交

发布经由影子、5% 金丝雀、受控区域扩展和完整试点。硬控制、任务质量、P95、新鲜度、审核负载和成本告警均指定负责人和运行手册。运维团队在接受所有权前演练过期政策、授权中断、工单注入、评估器漂移、安全关闭和回滚。
