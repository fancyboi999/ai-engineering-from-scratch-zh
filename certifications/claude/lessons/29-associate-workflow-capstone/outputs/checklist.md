# Associate 工作流综合项目检查清单

把这份清单用作综合项目的发布记录。用证据替换方括号中的提示。不要因为草稿看起来有说服力就把
项目标为完成。

## 星期一：目的与产品形态

- [ ] 决策、期限、受众和承担责任的负责人均已明确。
- [ ] 已记录允许和禁止的操作。
- [ ] 已按照组织政策对数据和后果分类。
- [ ] 所选 Claude 产品形态已获准用于该目的和数据类别。
- [ ] 已检查当前条款、数据保留行为、控制和限制。
- [ ] 已记录验证日期以及官方或合同来源。

证据：

```text
[Surface-selection record and policy approval]
```

## 星期二：来源与上下文

- [ ] 每个来源都有 ID、负责人、权威级别、生效日期、复核日期和敏感度。
- [ ] 已被取代或重复的材料不在活动检索范围内。
- [ ] 权威顺序已经明确。
- [ ] 必需的区域或业务单元均已包含，或已标记为缺失。
- [ ] 每周来源快照和截止时间已经固定。
- [ ] 冲突、过期来源和权限缺口都有负责人。

证据：

```text
[Registry version, snapshot ID, source exceptions]
```

## 星期三：Prompt 与任务设计

- [ ] 已包含结果、上下文、任务、证据、约束、格式和验收检查。
- [ ] 提取、核对、分析和起草是相互独立的阶段。
- [ ] 每个阶段都有可测试的输入、输出和门禁。
- [ ] 缺少证据时会拒答或升级，而不是猜测。
- [ ] 来源内容被视为数据，而不是工具授权。
- [ ] 已记录 prompt 和工作流版本。

证据：

```text
[Prompt versions and stage contracts]
```

## 星期四：验证与治理

- [ ] 发布候选通过 Python 校验器。
- [ ] 至少三个故意构造的失败包被阻塞或标记为需要修订。
- [ ] 精确总数和 schema 使用确定性检查。
- [ ] 每项有重大后果的主张都映射到提供支持的权威证据。
- [ ] 独立审核将发现与修订分开报告。
- [ ] 隐私、偏见、范围和操作权限检查通过。
- [ ] 移交前解决了每个阻塞项。

命令和结果：

```text
python3 code/main.py
python3 -m unittest discover -s code/tests -v

[Paste concise status and test count]
```

## 星期五：移交与恢复

- [ ] 移交中写明确切决策、期限和决策负责人。
- [ ] 包含来源快照、草稿版本和工作流版本。
- [ ] 通过的检查、失败的检查、冲突和不确定性均清晰可见。
- [ ] 提供批准、修订、拒绝和升级路径。
- [ ] 人工回退方案处于最新状态并经过演练。
- [ ] 外部操作与起草分开，并且有防止重复执行的保护。
- [ ] 审批后的来源变更会触发差异审核。

决策记录：

```text
决策：
决策负责人：
证据快照：
条件：
回退方案：
```

## 评估覆盖

- [ ] 四个有代表性的正常案例通过。
- [ ] 三个边界案例覆盖证据缺失、冲突或过期。
- [ ] 三个治理或对抗案例覆盖未授权目的、敏感数据或 prompt 注入。
- [ ] 高风险表现与聚合表现分开报告。
- [ ] prompt 调优期间始终不使用一个留出案例。

## 复盘


## 发布建议

- [ ] 保持人工处理。
- [ ] 继续使用影子模式。
- [ ] 作为经过人工审核的辅助工具发布。
- [ ] 允许对低后果步骤进行有限自动化。
- [ ] 因目的、数据、权限或证据尚未解决而停止并升级。

理由：

```text
[说明测试过什么、哪些项目通过、还存在哪些不确定性，以及谁负责该决策。]
```
