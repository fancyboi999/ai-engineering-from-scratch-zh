根据对模型 Demo 描述或其实际实现代码，依照以下清单逐一审查。将每项标记为 PASS（通过）、FAIL（未通过）或 UNKNOWN（未知），并给出确凿的判断证据：具体文件和行号、配置项，或引述描述原文。

若以下关键事实缺失，必须主动索取：

- 模型调用：使用云厂商 API 还是本地自建模型？典型延迟是多少？单次调用成本是多少？
- 目标受众：仅限内部团队、特邀审查人员，还是任何拥有链接的外部访客？
- 输入类型：允许的最大输入体量是多少？
- 部署与运行架构：使用的框架、底层 HTTP 服务器，以及链接的托管宿主。

审查清单：

接口契约（Contract）

1. 输入明确限制了数据类型、最大尺寸上限以及对控制字符的处理规则。
2. 服务端必须对上述每项限制进行二次校验。仅依赖浏览器端前端校验的判定为 FAIL。
3. Demo 为每个输出类别提供至少一个预置的快速体验示例。
4. 模型调用配置了硬超时时间（Timeout），且超时错误附带对用户具有指导意义的操作建议。

用户反馈（Feedback）

5. 请求运行期间，提交按钮必须处于禁用（Disabled）置灰状态。
6. 页面通过耗时计数器或进度指示器明确向用户展示模型正在处理中。
7. 文本响应采用流式传输（Streaming），且页面向用户展示首字生成延迟（TTFT）。
8. 流式开始后若发生后端故障，必须以错误事件（error event）形式传递给用户。静默挂断连接的判定为 FAIL。

错误处理（Errors）

9. 每个错误响应都具有固定的机器可读错误码（code）、包含关键数值的事实说明（message）、具备明确下一步动作的修复建议（hint），以及全局请求跟踪 ID（request_id）。
10. 任何错误响应中绝不包含原生堆栈追踪（Stack trace）、内部文件路径或密钥凭证。

公开链接防护（Public link）

11. 配备针对单客户端的速率限制（Rate limit，如令牌桶）。被限流请求返回 HTTP 429 状态码及 `Retry-After` 响应头。
12. 反向代理背后的限流键（Key）提取逻辑正确。客户端不得伪造或篡改自己的限流 Key。
13. 为整个 Demo 实例（面向所有客户端的总和）配置每日全局使用量上限或成本熔断限额。
14. 除非明确打算完全公开，否则访问必须经过 Token 校验、密码认证或单点登录（SSO）。
15. 限流与全局配额同样必须覆盖框架自动暴露的底层 API 路由。
16. 页面必须以纯文本形式渲染模型输出（如 `textContent`），绝不直接拼接插入 HTML。服务端下发 `Content-Security-Policy`（CSP）响应头。

日志与隐私（Privacy）

17. 服务端日志中绝不记录用户原始输入文本、带 Query 参数的完整 URL，以及明文客户端 IP 地址。
18. 框架自带的输入记录功能（如 Flagging 标错保存、历史记录、全量分析）默认关闭，或页面有明确声明告知用户。
19. 页面明确告知用户服务端保留了哪些信息。

产品化信号（Product signals）

20. 识别并汇报是否出现了以下信号：
    - 团队外部人员每周都在高频使用该 Demo。
    - 外部人员开始询问服务可用性（SLA/SLO）指标。
    - 用户提出需要账号登录、保存历史记录或导出结果。
    - 模型推理成本在财务预算中单独立项。
    - 输入数据触及法律合规、商业合同或个人隐私范畴。

产出物要求：

1. 包含检查项编号、判定结果与佐证证据的审查表格。
2. 针对每个 FAIL 项的修复清单，按风险由高到低排序：公开链接防护与隐私优先，其次是错误处理、接口契约，最后是前端反馈。每项修复必须明确指出具体文件、配置项或代码变更。
3. 识别到的产品化信号列表。若存在一条或多条信号，明确建议将该 Demo 迁移升级至正规生产级技术栈（包含真正鉴权、分布式追踪和分用户成本核算）。
4. 单行最终审查结论：可以直接公开分享、完成上述修复后可以分享，或必须先迁移至生产级技术栈。

一票否决规则（Hard rejects）。出现以下任意一种情况，严禁标记为可以直接公开分享：

- 服务端未校验输入内容大小。
- 允许外部公开访问的链接没有任何客户端限流或每日成本上限保护。
- 服务端日志或前端框架私自落盘存储了用户输入的文本，且页面未明确告知用户。

防伪兜底守则：

- 若受众范围未指明，一律默认视为面向公众完全开放。
- 若单次模型调用的具体成本未知，在开放公开链接前必须强制要求配置每日使用量上限。
- 若 Demo 基于 Gradio 或 Streamlit 运行，仔细核查其关于标错样本收集（Flagging）、公网临时共享链接与自动 API 路由的默认配置，切勿假定第三方框架默认行为在公网环境下是安全的。
