# Agent 辅助工程：任务证据

把这个模板复制到自己的仓库 `learning-artifacts/` 下。将提示替换为实际观察和相对证据路径。证据中不要包含私密数据和秘密。缺少的证据标为 `unverified`；绝不用编造的结果替代。

## 任务契约

- 仓库与起始版本：
- 学习者和预期用户或操作人员：
- Coding agent 与相关配置：
- 可观察目标与非目标：
- 允许路径和需要批准的操作：
- 任务界定与考虑依赖的计划：
- 验收主张与独立定义的预期结果：

## 自主权与环境

- 工作模式及理由，考虑不确定性、后果和可逆性：
- 实际时间预算；可获得时记录 token 或成本上限：
- 停止或升级条件、下一步和决策责任人：
- 选定的实现、调用方、测试与指令，以及理由：
- 保留的工具或扩展、任务需要、权限和上下文成本：
- 拒绝的 skill、MCP 工具、hook 或插件，以及理由：
- 重新检查的过时记忆或指令、当前来源，以及退役或替换决策：
- 该决策之后重跑的检查与证据：

只使用任务需要的扩展。无法取得的用量测量值应注明不可用。如果删除一条指令会丢失必要约束，保留经过重新验证的指令也是有效决策。

## 测试验收检查

使用可丢弃副本。在不破坏测试运行器的情况下，引入任务契约中的一个错误行为。第一次挑战时，保持验收检查不变。

- 刻意引入的错误结果：
- 应当拒绝它的预期断言或观察：
- 实际失败、精确命令、版本和证据路径：
- 如果错误结果通过，检查为什么太弱，以及如何改进：
- 恢复后的正确结果、通过的复跑和证据路径：
- 确认最终差异中没有刻意引入的变异：

语法错误、缺少依赖或配置失败，不能证明检查能发现行为缺陷。

## 运行与恢复

- 环境：`local`、`staging` 或 `live`：
- 运行版本或产物身份与观察时间：
- 失败信号、阈值、观察窗口、责任人和响应：
- 安全故障注入与观察证据：
- 已知正常的回滚目标与恢复步骤：
- 回滚演练、恢复行为和证据：
- 对持久数据的影响（如有）：
- 未验证的运行行为与主张边界：

本练习进行本地演练即可。准确标注，不要暗示它能证明生产行为。
