# 漂移监控与告警排查（Drift Monitoring）

此 Skill 适用于两类场景：A 部分用于模型即将上线发布、需要配置监控指标时；B 部分用于线上触发数据漂移告警时。

## A 部分：规划监控体系

### 第 1 步：按层级列出监控信号

| 层级 | 最低必备信号 |
|---|---|
| 系统健康度 | p99 延迟、错误率、每分钟请求数（RPM） |
| 输入特征 | 每个关键特征的单变量漂移检验、缺失值比例、新未知类别占比 |
| 预测输出 | 分数分布（在预测分数十分位上的 PSI）、正类预测概率 |
| 真实业务结果 | 设计阶段约定的离线业务指标，仅在带有真实标签的样本上计算 |

### 第 2 步：为各类特征选择检验方法

- 数值型特征：基准十分位分箱上的群体稳定性指标（PSI），外加双样本 Kolmogorov-Smirnov 统计量 $D$。
- 类别型特征：两行频数表上的卡方独立性检验（Chi-square test），外加 Cramér's V 效应量。
- 唯一值少于等于 5 个的离散数值特征：直接视作类别型特征处理。

### 第 3 步：设定时间滑动窗口

- 基准窗口（Reference window）：训练集数据，或者人工抽检确认正常的某段生产历史区间。
- 当前窗口（Current window）：样本量足够大，确保干净无漂移的正常数据不会突破警告水位线。可直接在历史无故障数据上回测确定该尺寸。
- 若线上流量存在显著的星期周期性，基准窗口必须覆盖完整的 7 天周期。

### 第 4 步：制定告警策略

在模型正式上线前，明确固定以下阈值参数：

```text
全局检验族显著性水平 (family alpha) = 0.01
单项检验显著性水平 (per-test alpha)  = family alpha / 检验特征总数 (Bonferroni 校正)
PSI 警告水位 / 确认漂移水位          = 0.10 / 0.25
KS 检验确认漂移门槛                 = D >= 0.10 且 p-value < per-test alpha
Cramér's V 检验确认漂移门槛         = V >= 0.10 且 p-value < per-test alpha
持续性规则 (persistence)            = 连续 2 个窗口均确认漂移才触发告警
结果指标告警                        = 实际指标连续 2 个窗口低于基准指标 - 容差阈值
```

警告（Warning）静默汇总到监控大盘；告警（Alert）直接通知值班工程师。

### 第 5 步：记录标签到达延迟

明确记录业务真实标签需要多少天才能延迟回流，以及在标签回流前团队通过什么代理指标监控效果。若延迟超过一周，引入基于校准后预测概率的性能估算方法。该估算方法能捕捉协变量漂移（Covariate drift），但无法探测概念漂移（Concept drift）。

## B 部分：排查分诊漂移告警

### 第 1 步：优先排查数据管道缺陷

首先排除以下看似是“数据漂移”的数据工程与管道故障：

- 上游数仓 Schema 变更、列名重命名或单位量纲改变（如分变元、秒变毫秒）。
- 缺失值出现异常峰值，或者被异常填充了系统默认兜底值。
- 因上游业务代码发布而新增的类别枚举，而非用户行为自然产生。
- 上游关联 Join 逻辑失效导致大量特征字段被置为 null。

### 第 2 步：界定漂移类型

| 观察证据 | 极可能发生的漂移类型 | 处置动作 |
|---|---|---|
| 输入特征分布显著偏移，但结果指标稳定 | 协变量漂移（Covariate drift） | 保持观测。仅当流量大面积滑入训练数据稀缺的边缘区间时，才需启动重训。 |
| 正样本比例发生偏移，但各类别的输入特征分布不变 | 先验漂移（Prior drift / Label shift） | 重新校准预测概率分数，或调整下游业务决策分类阈值。 |
| 输入特征分布完全稳定，但真实结果指标大幅暴跌 | 概念漂移（Concept drift） | 紧急收集最近期的真实标签，随后在近期的标注数据上重新训练模型。 |
| 输入特征偏移且结果指标显著下跌 | 带有破坏性的协变量漂移，或两者并发 | 在最新的标注数据上重新训练，并在最新历史区间上全面验证新模型。 |

### 第 3 步：评估效应量大小

在大样本数据量下，极微小的统计差异也会导致 p-value 极小。重点查阅 PSI、$D$ 或 Cramér's V 的真实数值，以及业务结果指标的实际变动幅度。按特征在模型中的重要性（Feature Importance）对发生漂移的特征进行优先级降序排序。

### 第 4 步：编写分诊报告

```text
告警概况：<信号指标, 窗口截止时间, 观测数值, 触发阈值>
管道检查：<发现的具体管道缺陷，或"无异常">
漂移类型：协变量漂移 | 先验漂移 | 概念漂移 | 不明确
业务影响：<结果指标变动幅度，或"标签回流中，预计回流日期 <日期>">
处置建议：观察等待 | 重新校准阈值 | 收集新标签 | 启动模型重训 | 立即回滚
负责人与复核日期：<姓名, 日期>
```

在执行任何模型重训练之后，必须将基准窗口同步重置为最新训练集的数据分布。
