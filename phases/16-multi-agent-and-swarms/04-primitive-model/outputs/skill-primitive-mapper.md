给定一个多 agent 框架（或使用该框架的代码库），产出四原语映射，让读者用一段话就能理解这个框架。

产出：

1. **Agent 定义。** agent 怎么构造？有哪些参数？携带什么状态？写出具体的类或工厂函数名。
2. **交接机制。** 它用的是三种交接模式中的哪一种：函数返回、图的边，还是发言人选择？如果是混合，以哪种为主？给出触发一次交接的最少代码。
3. **共享状态模型。** 完整消息池还是投影视图？内存中还是持久化（带检查点）？并发写入时是否线程安全？冲突由谁调和？
4. **编排器类型。** 静态、LLM 选择、交接驱动，还是队列驱动？若是 LLM 选择，默认用哪个模型？若是静态，图是有环的还是 DAG？
5. **跨轴权衡。** 各用一句话说明：确定性、扩展上限、可调试性、典型失败模式。

直接否决：

- 声称某个抽象是"新的"，却没有证明它无法归约为四种原语之一的任何映射。如果确实归约不了，准确说明缺口，而不是发明第五种原语。
- 只引用营销文档的框架对比。始终引用来自框架仓库或官方 cookbook 的具体代码示例。
- "框架 X 更适合做 agent"之类的说法，却不说明框架优化的是哪个原语。

拒绝规则：

- 框架闭源、公开文档也没有暴露 agent-交接-状态-编排器这一层时，说明不了解内部实现就无法映射。
- 用户提供了代码库但没有用框架（手写的 agent）时，改为映射这套自定义实现，并指出哪个原语设计不足。
- 框架早于 2024 年（原版 AutoGen v0.2、Swarm 之前）且已不再维护时，加一行说明其后继者是否保留了同样的映射。

输出：一页框架简报。开头用一句话总结（"框架 X 把交接固定为图的边，并通过 reducer 暴露共享状态。"），然后是上面五个部分，最后用一段话说明这个框架的原语最适合哪类生产项目。
