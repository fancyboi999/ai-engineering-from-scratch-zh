给定自己构建的字节码容器，生成头部报告、一个函数的清单，以及容器在指令之外保存哪些信息的表格。此 skill 可用于 Claude、Cursor、Codex、OpenClaw、Hermes 或任何读取 SKILL.md 的 agent。

## 必需输入

- 字节码文件，以及生成它的编译器、解释器或汇编器的精确版本和命令。
- 构建所用源码，与字节码一起保存。
- 从同一文件采集、由格式自身工具输出的参照清单：pyc 使用 `python3.N -m dis`，class 文件使用 `javap -c -p`，模块使用 `wasm-objdump -h -x -d`，程序集使用 System.Reflection.Metadata 转储或 `ilspycmd -il`。
- 第 43 课的读取器（`code/main.py`），或遇到未知类型码、操作码或表就报错的等价实现。
- 需要报告的函数。

## 流程

1. 根据起始字节识别容器：两个字节后跟 `0d 0a` 是 pyc，`ca fe ba be` 是 class 文件，`00 61 73 6d` 是 Wasm 模块，`4d 5a` 且设置数据目录 14 是 .NET 程序集。全部不匹配则停止。
2. 读取头部并记录版本事实：pyc 魔数字和标志、class 主次版本、Wasm 二进制版本、CLI 运行时版本和元数据版本字符串。给出这些事实允许识别的生成器版本。
3. 用读取器读取整个容器。pyc 提供模块代码对象及嵌套代码对象；class 文件提供常量池、字段、方法和属性；模块提供节、类型、导入、导出、代码体、数据及 name 节；程序集提供流、表行数、TypeDef、MethodDef、Param、Field 行和方法体。
4. 反汇编选定函数。对 pyc，只有当前解释器写入文件时才使用 `dis`，否则使用匹配解释器的采集清单。其余三种使用读取器的反汇编器。
5. 按偏移、字节和助记符，将清单与参照比较。首次不一致就停止并修正读取器。记录一致的数量。
6. 为函数填写事实表：函数名、参数名、参数类型、返回类型、局部变量名、行号、函数体大小，以及控制流形状（跳转、switch 指令、嵌套块）。
7. 写明容器丢失的事实和它们应存放的位置：.NET 局部变量名在 PDB，Wasm 名称在 name 自定义节，JVM 局部变量名需要 `javac -g`，原生代码需要 DWARF。
8. 运行任何反编译器前，检查其文档所列版本上限是否覆盖步骤 2 的头部版本。记录上限及该主张来源。

## 必需报告

- 容器、生成器版本、构建命令和参照清单命令
- 头部事实及其原始字节
- 参照一致性，以一致行数除以比较行数表示
- 带偏移、字节和文本的函数清单
- 每行标为保留或丢失并附证据的事实表
- 考虑过的反编译器、版本上限，以及文件是否在支持范围内
- 读取器无法解释的每个字节范围及偏移

## 必须拒绝的做法

- 从文件名而非头部字节猜测生成器版本。
- 用不同解释器版本的 `dis` 模块列出 pyc 指令。
- 将 class 文件分支目标解释为相对下一条指令。JVMS 规定它相对于分支操作码。
- 跳过 `tableswitch` 和 `lookupswitch` 前的对齐填充。
- 将 Wasm 导出名当作局部变量名，或将缺少 name 节等同于剥离符号的二进制。
- 读取 .NET token 时不检查表字节，或计算行大小时不使用 HeapSizes 位和行数。
- 因反编译器输出不支持的操作码而声称容器经过混淆。
- 与同一源码另一次构建采集的参照清单比较。

## 产出

返回以下章节：

1. 容器与版本：头部字节及其识别的生成器。
2. 参照：比较行数、一致行数，以及存在时的首次不一致。
3. 清单：带偏移、字节和文本的函数。
4. 事实：名称、参数、类型、局部变量、行号、大小、控制流形状，每项标为保留或丢失并附证据。
5. 反编译器限制：考虑的工具及文档上限，与头部版本比较。
6. 未知项：读取器跳过或拒绝的每个偏移及原因。

以首个未知项收尾。没有未知项时，给出参照一致数量，以及六项事实中容器保留的数量。
