# 九种图形

根据断言为每张图选一种类型，再使用以下布局。坐标均为宽 640 的 viewBox 单位，内容位于 x 20 至 x 620。

| 类型 | 用途 |
|---|---|
| `sequence` | 参与方生命线，时间向下，交互编号 |
| `structure` | 单个记录、对象或 schema 的结构 |
| `flow` | 数据经过的阶段及读写者 |
| `comparison` | 并排比较同一问题的两种答案 |
| `timeline` | 提交序号或时间等数轴上的多条轨道 |
| `tree` | 所有权、包含或委托 |
| `state` | 状态机与转换 |
| `decision` | 失败位置与结果含义 |
| `layers` | 各层及其拥有的部件 |

## sequence

- 顶部参与方框位于 y 8 至 10，高 30 至 40，中心对齐生命线 x。
- 四通道中心约为 x 118、262、406、556，框宽 112。七通道中心为 `52 + i × 89`，框宽 86，标题 11，内边距 3。
- 生命线从框底延伸到 `H − 8`。
- 每行间隔 44 至 46，首行 y 76 至 84。
- 每行步骤圆在 x 16 至 24，按运行记录顺序编号。
- 箭头水平，标签在线上方 6 单位，注释在线下方 15 单位。
- 高度约为 `首行 + 行数 × 44 + 30`。八行适合高 430，十行适合高 540。

## structure

- 记录色表头高 28，记录名左对齐。
- 每字段一行，高 28，纸张色填充，panel-edge 描边。
- 字段名 x 32、字号 12、ink-soft。值 x 150、字号 12、ink。
- 右侧注释 x 380、字号 11、衬线。
- x 350 至 x 372 的短线使用记录色，将注释连到对应行。
- 左侧 x 20 放记录小标题，右侧 x 380 放“各字段的用途”。
- 六个字段适合高 226。

## flow

- 顶部小标题分别标明写入者、阶段、读取者。
- 写入者在左列 x 20，框宽 130、高 38，间隔 46。
- 阶段放在持久状态色的容器内，每框宽 72，间距 10。
- 读取者在右列 x 530，宽 90。
- 写入者以 `call` 路径连接队列，读取者通过 `event` 路径获取帧。队列下方的外部影响以 `effect` 箭头返回。

## comparison

- 两列分别从 x 20 和 x 336 开始，各宽 284。
- 中间 x 320 放竖向虚线。
- 小标题为 `A · <第一种答案>` 和 `B · <第二种答案>`。
- 两列行数相同，行距 70，框高 44。
- 对比主题的两种行为，不与自己的旧版本对比。

## timeline

- 每条轨道的小标题位于 x 20。
- 条带高 12。工作使用色相 ink 实条，等待用斜线条，恢复或计划工作用虚线轮廓。
- 数轴从 x 60 至 x 620，每 40 单位一个高 8 的刻度。
- 每个刻度下方放字号 11 的数值。
- 轴下方用小标题标单位，例如 `Commit seq`。
- 跨所有轨道的事件用线宽 1.4 的竖虚线表示，上方有粗体标签。

## tree

- 根框居中，x 230，宽 180。
- 子节点在下方 94 单位处同一行，x 20、230、440，框宽 180、高 44。
- 边用 ink-mute 正交路径，无箭头，先从父节点向下，再横向，再向下接入子节点。
- 用一个简短衬线标签说明关系，例如“拥有”。

## state

- 活跃状态在左侧，终止状态在右列 x 470、宽 150。
- 终止列上方放“终止”小标题。
- 所有转换用 `state` 样式，即琥珀色虚线。
- 分支先经过同一个连接 x，例如 380 或 430，再转入各目标。
- 终止状态用双边框，中断状态用虚线。
- 转换标签为 11 衬线、ink-soft，放在线旁，不压线。
- 底部一行衬线说明：“双边框：终止 · 虚线：中断”。

## decision

- 顶部一行放各阶段，首框 x 20，宽 110，间距 120。
- 下方结果行约位于 y 118。
- 安全结果用青色，未知或不安全结果用玫红。
- 阶段到结果用 `call` 箭头，失败位置用 `fail` 箭头。
- 最后一行说明各结果的下一步，用 `reply` 箭头连接。

## layers

- 各层小标题在 x 20，下面放该层方框或容器。
- 主栈宽 440，x 20 至 x 460。右列 x 480、宽 140 放可选项或插件，以虚线连接。
- 层内组件宽 98，间隔 106。
- `call` 箭头从宿主向下，`write` 箭头向下进入存储。用一个标签说明规则，例如“每次变更都是一次提交”。
