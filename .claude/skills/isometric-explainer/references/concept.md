# 构思机器

每个部件执行流程的一步。运行一次后，读者不看图注也应能解释流程。

## 一句话检查

先写：

> X 经过 Y 移动，这个运动表示 Z。

符合要求的例子：

- 请求卡随车架经过一圈工位，每圈表示一次模型轮次。
- 请求卡停在探针下，探针找到已存副本表示缓存命中。
- 纸条经过 schema 检查尺和权限锁，停下表示工具调用被拒绝。

一句话需要两次说“代表”时，机器过于抽象。选择能实际执行动作的物体：抽屉存文档，压机造新物，量尺测量，锁闩阻止通过。

## 按职责选物体

| 概念 | 物体 | 表达含义的动作 |
|---|---|---|
| 有序步骤 | 轨道与车架 | 按顺序停在工位 |
| 存储条目 | 抽屉、箱、架 | 卡片进入或离开 |
| 昂贵工作 | 压机、曲柄、计算器 | 压头下降、曲柄旋转 |
| 检查 | 指针尺、压杆 | 一致时指针为零，不一致时偏转 |
| 阻止 | 锁闩、门锁 | 滑动关闭或保持锁住 |
| 限制或预算 | 计数器、象限盘、表盘 | 指针前进，到上限停止 |
| 记录 | 打印机和纸带 | 每事件打印一行 |
| 固定知识 | 内含滚筒的密封壳 | 只在展开视图看到滚筒 |

## 概念映射到工位

几何前先列表，每工位一行：

| 字段 | agent 工作台示例 |
|---|---|
| 部件 | 校验尺 |
| 铭牌 | VERIFIER |
| 是什么 | 模型外的答案检查 |
| 做什么 | 压杆压下，重新计算数值 |
| 为什么 | 写出答案的模型不适合独自评判答案 |
| 缺少时 | 未检查答案直接流向出口 |

检查面板、铭牌、导览都使用同一张表，保存在一个内容模块中。

## 主动触发故障

列出读者可造成的故障，每项对应模型中的开关或 fault 值。参考页有检索、工具访问、校验三个开关，四种 fault：none、超时一次、始终超时、格式错误。共有 2×2×2×4=32 种运行，测试全部覆盖。

每个有价值的故障一个场景按钮。参考页有八个，例如“工具调用格式错误：schema 检查拒绝”。

## 估算规模

根据清单统计部件，不从图片估计。一个部件是审阅者能指出的实体、运动组或线集。

| 规模 | 部件 | 时间 | 常见用途 |
|---|---|---|---|
| 图表 | 40 至 80 | 约 1 小时 | 课程中一个机制 |
| 主图 | 80 至 150 | 2 至 4 小时 | 五至十工位的独立页 |
| 更大 | 超过 150 | 先询问 | 开始前取得用户批准 |

写几何前说明规模与部件数。构建中超出规模时，暂停并询问。

## 如实标注

说明什么是模拟。参考页的说明为：

> 这是模拟。模型步骤由固定脚本读取车架卡片并选择下一步，浏览器中没有运行真实模型。账单、算术和检查都实际执行。时间是模拟设定的固定成本，并非实测。

沿用这个结构：指出脚本部分、真实执行部分，以及固定时间成本。
