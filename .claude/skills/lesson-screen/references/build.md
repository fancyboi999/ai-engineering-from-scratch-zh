# 边学边制作图表

自制图表是导师在教学期间为一节课制作的单页。本文规定制作阶段、页面契约、制作准则和 3D 要求。

## 制作阶段

每次制作经过六个阶段。进度屏幕显示这些阶段，每完成一个阶段就更新。

| 阶段 | 完成条件 |
|---|---|
| 概念 | 用一句话说明什么在运动，以及运动的含义 |
| 事实 | 数值来自课程运行，状态模型测试通过 |
| 部件 | 部件清单将每个概念映射为部件，每个工位映射为标签 |
| 绘制 | 页面能构建并打开，控制台无错误 |
| 检查 | 已查看明暗主题、桌面及手机宽度的 `CLI shot` 截图 |
| 就绪 | `CLI publish` 已将页面放到屏幕上 |

每次制作使用独立目录：`.lesson-screen/builds/<phase>-<lesson>-<form>/`。源文件、测试、页面和截图都放在其中。

## 制作进度屏幕

学习者接受后立即写入。每个阶段结束时用新文件名写入更新。

```html
<p class="ls-eyebrow">第 07 阶段 · 第 16 课 · 制作中</p>
<p class="ls-lead">正在制作推测解码的等距机器。</p>
<ol class="ls-building">
  <li class="is-done">概念：草稿 token 经过验证器，由它接受或拒绝</li>
  <li class="is-done">事实：接受率来自课程运行，6 项模型测试通过</li>
  <li class="is-now">部件</li>
  <li>绘制</li>
  <li>检查</li>
  <li>就绪</li>
</ol>
<p class="ls-note">继续在终端学习。图表准备好后会出现在这里。</p>
```

## 页面契约

自制图表是完整 HTML 页面，既可在学习屏幕中展示，也可从磁盘打开。

- 使用课程明暗主题的设计 token 与字体，见 course-style 技能。
- 主题读取 `localStorage.theme`，没有时跟随系统。监听 `storage` 事件，使顶部主题切换能传入页面。
- 脚本只从页面自身、aieng-zh.cn 或 cdn.jsdelivr.net 加载。固定精确版本。字体可从 Google Fonts 加载；其他资源受服务器的 CSP 限制。
- 存在 `window.lessonScreen` 时，通过 `window.lessonScreen.send(event)` 发送点击。使用 SKILL.md 中的事件类型。从磁盘打开时该对象不存在，用短提示代替提问按钮。
- 在 1440 × 900 窗口中，图表、控件和数值无需纵向滚动。在 390 px 宽度下堆叠部件，不出现横向滚动。
- 显示课程路径和以“核心思想”开头的一句话。
- 注明图表由导师制作，未经课程作者审阅。
- 页面隐藏时暂停运动。减少动态效果模式下显示每一步的结束状态。
- 设置清晰的 `<title>`，学习屏幕顶部会显示它。

## 制作准则

每种形式都要检查以下规则。

1. **物体就是解释。** 设计一个工作方式能表达概念的真实物体。缓存键可以是锁，所有锁销都要匹配；队列可以是托盘架；注意力可以是将每个 token 连到此前 token 的交换台。
2. **物体必须可辨认。** 带标签的盒子、悬浮板片、散落的立方体或圆锥不足以表达系统。
3. **小部件各司其职。** 按底座、结构、机构、控件和主体分组。部件有支撑关系，并包含倒角、螺丝、接缝、铭牌、刻度和带接头的线缆。
4. **只用一种强调色。** 标出当前步骤应关注的部件，其余部分使用墨色、纸色和金属色。
5. **分步教学。** 编号步骤栏每步只发生一个变化，提供自动与手动模式。状态模型同时驱动部件和读数。
6. **每个工位都有标签。** 标签用引线连接工作部件，不遮挡运动部件或其他标签。
7. **主体占据合适空间。** 占舞台的 55% 到 70%。除非概念要求，部件都有支撑。
8. **运动平稳。** 使用缓动或弹簧运动，没有变化时停止循环。

规则 1 或 2 不满足时，图表尚未就绪。

## 形式

- **蓝图。** 遵循 blueprint-figure：选择一种图形、纸面背景、蓝图强调色，并完成可读性检查。将 SVG 包装成符合页面契约的完整页面。
- **机制图。** 遵循 motion-figure 第 2 层：真实名称和数字、一个控件、经过计算的结果。
- **等距机器。** 从 isometric-explainer 的状态模型做到验证循环。它的组件绘制带轮廓、阴影和拆解效果的实体部件。已安装的等距插画技能可以补充细节、WebGL 效果或 3D 模式，仍遵守页面契约。
- **3D 模型。** 宿主有支持 3D 的图表技能时使用它，否则按下列规则编写 three.js 页面。

## 3D 要求

学习者旋转模型来观察深度。

- 用 cdn.jsdelivr.net 的 import map 固定 three.js 精确版本，addons 使用同版本。
- 用精细部件建模：圆角实体、旋转体、线缆管、螺丝、接缝和刻字铭牌。不能仅堆叠基础几何体。
- 使用与背景同色的地面及雾，不露出地平线边缘。
- 用环境贴图和仰角约 65 度的主光照明。软阴影紧贴模型，部件与阴影相接。
- 使用拉丝金属、玻璃、陶瓷、橡胶和喷漆塑料等物理材质。
- 使用平滑法线、屏幕宽度恒定的反向外壳画细轮廓。按角度检测边缘无法识别圆滑部件的轮廓。
- 根据模型投影边界调整相机，使主体占舞台的 55% 到 70%。
- 与其他形式一样，展示步骤、读数和标签。
- 提供相同部件的蓝图视图：正交等距相机、纸色填充、蓝图线条，以及模型外的标注。
- 仅在内容变化时渲染。没有 WebGL 时，以文字显示步骤、部件和读数。

## 检查成品

1. 以默认 1440 × 900 尺寸运行 `CLI shot <page.html> --theme light` 和 `--theme dark`。
2. 再以 `--width 390 --height 844` 分别截取两种主题。
3. 截取一个中间步骤。页面应支持用查询参数跳转，例如 `CLI shot "page.html?step=3"`。
4. 查看每张图像：物体是否可辨认？标签是否清楚且无重叠？数字是否与课程运行一致？
5. 修正问题并重新截图，三项都通过后发布。

没有本地 Chrome、Chromium 或 Edge 时，`CLI shot` 给出明确错误。向学习者说明尚未目视检查，再发布。
