# 接受幂等完成回执

> 属于错误租约的正确结果，仍是过期结果。

**类型：** Build
**语言：** Go
**前置要求：** 完成阶段 1 至 2；理解其导出类型和失败契约。
**阶段：** 第 3 阶段，共 4 阶段
**预计时间：** 约 2 小时

## 构建内容

为一个租约接受一个结果。在初始化工作区实现 `stage3.go`。提供的 CLI 调用你的实现，不导入参考方案。

## 推演机制

结果绑定分片、所有者和版本。假设 old/v1 算对答案，但 new/v2 已完成分片。提交 old/v1 必须在比较结果文本前失败。worker 的智能不赋予它当前写入权限。

完成前要求 now < Until，结果非空且最多 1 MiB。完成后，同一所有者、版本和完全相同的结果可再次成功交付，即使租约时间已过。这是确认既有回执，不是重新开放评估。更改任何结果字节都会冲突。

CLI 对提供的已记录响应和预期文本转小写、压缩空白后比较。`GET` 与 ` get ` 匹配；`no` 与 `yes` 不匹配。各分片回执存储有序案例 ID、正确性标记和实际 worker PID。协调器在写入持久化 Lease.Result 前验证回执覆盖与计数。

这是狭窄的精确匹配评估器，不能评判转述、引用支持或模型推理。先定义稳定评分版本并纳入运行身份，再替换评估器。

```figure
pj-distributed-eval-farm-3
```

## 你的契约

```go
func Submit(l *Lease, worker string, version int, now int64, result string) error
```

保留 `types.go` 中的公开签名和错误。被拒绝的调用必须保留调用者此前状态。阅读[项目 API](../../../API.md)，了解最终产物的文件与进程边界。

## 实现提示

先检查所有者与版本，再处理已完成结果。仅首次完成应用到期条件；此顺序允许相同回执重新交付。

## 探索一次失败

在 109 完成，200 时重新交付相同数据，再更改一个结果字节。预测三种结果。尝试旧所有者配相同数据，解释为何仍失败。
