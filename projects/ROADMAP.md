## 构建顺序

从适合自己级别的项目开始，完成链接的前置项目。链接区分就绪和规划前置项目。没有前置项目的入门计划假设你已了解所选语言基础。未来实现应先在自编本地 fixture 上产生有用结果，再解释一个可见失败，最后加入可复用导出或 adapter。外部 SDK 和 provider 检查保持明确。

每份简介定义自己的任务与验收边界。实现时添加原创 fixture、留出案例、有来源支持的解释、可编辑机制图和真实输出录制。参考链接介绍协议和格式，不是规划工具已实现的证据。

## 级别 1：入门

<a id="photo-burst-contact-sheet"></a>

### 连拍照片联系表

用简单的像素指纹和可检查的清晰度指标，帮助创作者审阅重复拍摄。将疑似重复照片分组，保留摄影者的最终选择，为编辑器导出联系表及选择清单。

**独立重点：** 视觉证据库搜索给定文本区域；本项目比较真实图像像素，辅助选片。

**首先构建的演示：** 将原创几何场景图像的模糊、裁剪和曝光变体分组，同时让另一场景保持独立。

**语言：** Python

**交付物：** HTML 和 PNG 联系表、相似性解释及 selections.json

**基于：** 无；从所选语言基础开始。

拟定里程碑：

1. 解码图像并保留源尺寸
2. 计算像素指纹和清晰度指标
3. 将相似照片分组供人工选择
4. 导出联系表和编辑器选择清单

## 级别 2：构建

<a id="dependency-upgrade-impact-map"></a>

### 依赖升级影响图

用给定的升级前后 API 签名和有界源码解析器，帮助维护者评审升级。将改变的符号映射到真实调用位置，区分已确认的不兼容和未解决的用法，生成针对性测试清单。可选模型可以解释证据，但不能编造已删除的 API。

**独立重点：** PR 评审报告器检查变更行；本项目把新旧依赖契约关联到整个仓库的调用位置。

**首先构建的演示：** 修改一个自编库的签名，找出两个受影响调用者和一个未解决的动态调用。

**语言：** Python, TypeScript

**交付物：** 调用位置影响图、SARIF 发现及针对性测试清单

**基于：** [PR 评审报告器](pr-review-reporter/)

拟定里程碑：

1. 读取给定的新旧 API 契约
2. 索引支持的导入和调用形式
3. 将签名变更关联到受影响代码
4. 导出发现并保留未解决案例

<a id="gesture-shortcut-pad"></a>

### 手势快捷操作板

用少量自行录制的手势，帮助演讲者或教育者控制本地练习应用。规范化指针笔画，用明确的序列距离算法比较，暴露不确定匹配，并导出可移植手势配置及小型浏览器集成演示。

**独立重点：** 桌面控制执行坐标动作；本项目从指针手势学习标签，并集成到本地应用。

**首先构建的演示：** 画出三种原创手势来导航虚构幻灯片，并检查一条有歧义的笔画。

**语言：** TypeScript

**交付物：** 交互手势板、gesture-profile.json，以及供其他浏览器应用使用的标签事件

**基于：** 无；从所选语言基础开始。

拟定里程碑：

1. 捕获并规范化原创指针笔画
2. 用可检查的距离函数比较笔画
3. 审阅不确定匹配并补充更好的示例
4. 导出手势配置并演示应用集成

## 级别 3：工程

<a id="ci-failure-reproducer"></a>

### CI 失败复现器

根据导出的工作流日志、提交标识和声明环境，帮助贡献者复现失败作业。定位首条失败命令，区分基础设施失败与测试失败，生成白名单内的本地重放方案。每条生成指令旁保留原日志行。

**独立重点：** 微型编码 agent 修补本地工作区；本项目从失败 CI 作业恢复环境和最少重放步骤。

**首先构建的演示：** 将一个自编失败作业缩减为三步本地复现，同时保留原失败行。

**语言：** Python, TypeScript

**交付物：** 复现清单、不经 shell 的重放 CLI 和 HTML 失败简介

**基于：** [微型编码 agent](tiny-coding-agent/)、[PR 评审报告器](pr-review-reporter/)

拟定里程碑：

1. 规范化作业步骤及源行范围
2. 区分最初失败和下游噪声
3. 构建明确的重放方案
4. 运行获准的本地命令并比较证据

主要参考：[参考 1](https://docs.github.com/en/actions/how-tos/monitor-workflows/use-workflow-run-logs)。

<a id="label-adjudication-desk"></a>

### 标签裁决台

帮助小团队建立有用的评估标签，不悄悄用多数票抹掉分歧。导入独立标注记录，审阅时隐藏标注者身份，将分歧分组，记录明确的最终决定及证据。导出本地审阅页和版本化 JSONL，保留原标签和裁决历史。

**独立重点：** 数据集划分审计器检查数据分离，反馈主题板将评论分组；本项目产生可问责的人工评估参考标签。

**首先构建的演示：** 审阅自编标注集中的三处分歧，导出已接受决定和一个未解决案例。

**语言：** Python, TypeScript

**交付物：** 本地裁决 UI、一致性报告和保留来源的标注 JSONL

**基于：** [数据集划分审计器](dataset-split-auditor/)、[反馈主题板](feedback-theme-board/)

拟定里程碑：

1. 导入独立标签并保留记录来源
2. 测量一致性并建立盲审队列
3. 记录有证据支持的裁决决定
4. 导出版本化标签并保留未解决案例

**范围边界：** 保留未解决判断和原始一致计数。标注者间一致性衡量的是一致程度，不是标签的客观真值。

<a id="lost-item-match-desk"></a>

### 失物匹配台

帮助社区场所将失物描述与拾获物照片匹配。组合明确文本特征、简单图像颜色描述符和可选的已审阅视觉提案，导出 HTML 候选配对台及决定文件，接入场所现有记录。

**独立重点：** 目录记录关联器对齐结构化记录；本项目用独立的文本与图像证据教授多模态候选匹配。

**首先构建的演示：** 将两个相似瓶子和一把伞的原创照片与自编描述比较，让有歧义的瓶子保持未解决。

**语言：** Python

**交付物：** HTML 物品配对审阅台、特征解释及 match-decisions.json

**基于：** [目录记录关联器](catalog-record-linker/)、[连拍照片联系表](#photo-burst-contact-sheet)（规划中）

拟定里程碑：

1. 导入物品描述、照片和登记标识
2. 独立计算文本与图像特征
3. 排序候选配对并审阅冲突证据
4. 导出匹配决定及其源记录

<a id="presentation-rehearsal-coach"></a>

### 演讲排练教练

将给定幻灯片文本与带时间的转录片段对齐，帮助演讲者改进排练。计算明确的节奏与主题覆盖信号，展示建议练习目标背后的源短语，导出逐幻灯片 HTML 报告及可复用排练对比文件。

**独立重点：** 会议纪要转行动提取承诺；本项目将讲述内容与计划视觉材料对齐，支持刻意排练。

**首先构建的演示：** 比较两次原创三页幻灯片排练，找出跳过的定义及支持它的转录范围。

**语言：** Python

**交付物：** 关联幻灯片的 HTML 排练报告、coverage.json 和两次排练对比

**基于：** [语音笔记转录流水线](voice-note-transcriber-pipeline/)、[语义笔记搜索](semantic-notes-search/)

拟定里程碑：

1. 导入幻灯片文本和带时间的排练片段
2. 将讲话片段对齐到候选幻灯片
3. 测量节奏并审阅疑似覆盖缺口
4. 导出排练报告并比较第二次尝试

<a id="semantic-cache-correctness-lab"></a>

### 语义缓存正确性实验

构建显式启用的答案缓存，将条目绑定到租户、模型、来源版本和过期时间。用自编近似但不同的问题比较精确匹配与语义候选，包括数字变化和否定。导出本地 HTTP adapter 和误命中报告；相似性本身不能授权跨用户复用。

**独立重点：** RAG 新鲜度流水线为来源内容管理版本；本项目在身份与新鲜度约束下，决定旧答案能否用于新问题。

**首先构建的演示：** 展示改述问题命中缓存，而关键数字或租户变化时未命中。

**语言：** Go, Python

**交付物：** 本地缓存 adapter，以及误命中、延迟和失效报告

**基于：** [语义笔记搜索](semantic-notes-search/)、[RAG 新鲜度流水线](rag-freshness-pipeline/)

拟定里程碑：

1. 定义身份、新鲜度和隐私边界
2. 实现精确匹配查询与失效
3. 用对抗问题对评估语义候选
4. 导出有界 HTTP adapter 和复用证据

主要参考：[参考 1](https://www.rfc-editor.org/rfc/rfc9111.html)。

<a id="tool-contract-migration-checker"></a>

### 工具契约迁移检查器

帮助工具作者演进可调用接口，而现有 agent 仍持有旧参数形状。比较文档化的新旧 schema 子集，为必填字段和收窄取值生成反例，在两个校验器中重放已保存调用。导出兼容性报告和可评审的 CI 迁移 fixture。

**独立重点：** JSON Schema 输出守卫校验一个载荷；本项目分析两份工具契约的兼容性，给出有效性发生变化的具体调用。它不把包升级映射到源码调用位置。

**首先构建的演示：** 为虚构目录工具添加必填参数，生成一条在旧契约通过、在新契约失败的保存调用。

**语言：** TypeScript, Python

**交付物：** schema 兼容性 CLI、破坏性调用 fixture 和 CI 报告

**基于：** [JSON Schema 输出守卫](json-schema-output-guard/)

拟定里程碑：

1. 加载版本化工具契约和已保存调用
2. 分类支持的 schema 变更
3. 生成并重放失效调用反例
4. 导出迁移 fixture 和兼容性门禁

**范围边界：** 公布支持的 schema 子集，将未处理关键字标为未解决，而不是宣称完整 JSON Schema 兼容。

<a id="video-highlight-storyboard"></a>

### 视频高光故事板

从给定视频、帧样本和带时间的转录中，帮助教程创作者组装短片段。结合可见镜头变化和转录主题分数，保留精确源时间范围，导出可播放故事板及视频编辑器使用的剪辑决定 JSON。

**独立重点：** 语音笔记转录流水线生成字幕；本项目结合视觉与转录时间，选择可编辑的视频序列。

**首先构建的演示：** 从原创折纸教程选出精简介绍与演示，不在句子中途切断。

**语言：** Python

**交付物：** 带时间戳的 HTML 故事板、选中缩略图及 edit-decisions.json

**基于：** [语音笔记转录流水线](voice-note-transcriber-pipeline/)、[连拍照片联系表](#photo-burst-contact-sheet)（规划中）

拟定里程碑：

1. 对齐视频元数据、帧样本及转录时间
2. 生成镜头和主题边界候选
3. 在时长预算内审阅片段选择
4. 导出故事板和面向编辑器的时间范围

## 级别 4：系统

<a id="a2a-task-handoff-workbench"></a>

### A2A 任务交接工作台

帮助团队连接具有不同能力和任务生命周期的 agent。读取 Agent Card，选择双方支持的 binding，运行包含补充输入请求、取消和最终产物的交接。导出本地客户端与服务器对，以及展示每次状态转换和产物归属的可重放回执。

**独立重点：** 多 agent 代码评审面板为单一目的协调本地评审者；本项目测试独立协议参与者间的任务交换。

**首先构建的演示：** 让两个本地 agent 组装自编工作坊简介，为一项缺失输入暂停，并交换最终产物。

**语言：** Python, TypeScript

**交付物：** 两个本地 agent 端点、交接客户端和任务／产物重放包

**基于：** [Mastra 类型化工作流 agent](typed-workflow-agent-with-mastra/)、[agent 追踪调试器](agent-trace-debugger/)

拟定里程碑：

1. 读取 Agent Card 并选择支持的接口
2. 创建任务并保留消息标识
3. 处理输入请求和取消
4. 交换产物并重放完整交接

**范围边界：** 实现时选定并固定 A2A 协议修订版、binding 和 SDK 版本。宣称支持前，用真实本地端点验证线协议兼容性与能力声明；可选扩展保持明确。

主要参考：[参考 1](https://a2a-protocol.org/latest/specification/)。

<a id="abstention-calibration-workbench"></a>

### 弃答校准工作台

为有界任务制定有依据的接受或转交规则。在明确错误成本下，用带标签开发记录调分数阈值，冻结策略，再按切片评估留出风险与覆盖率。导出决定策略文件和审计，显示多少请求需要人工复核。

**独立重点：** 本地模型评估框架报告模型表现与校准；本项目通过独立阈值选择阶段，把分数转成实际转交策略。

**首先构建的演示：** 在自编开发集上调整转交阈值，冻结后展示它在留出集上的不同覆盖率。

**语言：** Python

**交付物：** 冻结的接受／转交策略 JSON、风险覆盖曲线和留出切片审计

**基于：** [数据集划分审计器](dataset-split-auditor/)、[本地模型评估框架](local-model-eval-harness/)

拟定里程碑：

1. 校验相互分离的开发与留出记录
2. 按声明错误成本调整阈值
3. 冻结策略并评估留出切片
4. 导出决定 adapter 和审阅量估计

**范围边界：** 输入分数不自动等于概率。报告经验结果和不确定性，不凭小数据集承诺整个部署的错误上界。

<a id="artifact-provenance-gate"></a>

### 产物来源门禁

帮助维护者在集成前检查下载的 agent 插件或发布产物。验证主体摘要及证明签名，按明确策略评估声明的构建者与来源身份，保留每次拒绝的原因。导出 CI 门禁、自编签名 fixture 和另行验证的外部校验器 adapter。

**独立重点：** 跨 agent 技能安装器写入本地技能包；本项目在接受外部构建包或二进制前，检查产物来源和构建证据。

**首先构建的演示：** 验证自编签名产物，修改一字节后拒绝，再独立拒绝不受信构建者的签名。

**语言：** Go, Python

**交付物：** 产物校验 CLI、信任策略文件和来源决定 JSON

**基于：** [跨 agent 技能安装器](skill-installer/)、[SKILL.md 校验与加载器](skill-validator/)

拟定里程碑：

1. 将产物字节绑定到证明主体
2. 按明确信任根验证签名
3. 评估构建者与源材料策略
4. 导出带可复现拒绝 fixture 的 CI 门禁

**范围边界：** 固定支持的证明格式和校验器版本。来源校验建立特定来源声明，不代表内容安全或自动取得 SLSA 认证。

主要参考：[参考 1](https://slsa.dev/spec/v1.2/provenance)。

<a id="context-compaction-verifier"></a>

### 上下文压缩校验器

帮助 agent 开发者避免在长会话中丢失用户约束。追踪带来源定位的明确事实与约束，创建抽取式压缩上下文，按声明的保留契约测试候选摘要。导出压缩中间件，在必需证据消失时保留旧快照。

**独立重点：** 持久记忆服务器存储持久记录；本项目在替换工作上下文前，按明确约束验证一次活跃会话压缩。

**首先构建的演示：** 压缩一段容易遗漏必需输出格式的自编会话；约束消失时恢复旧快照。

**语言：** Python, Rust

**交付物：** 压缩中间件、约束保留回执和可恢复上下文快照

**基于：** [持久记忆服务器](memory-server/)、[token 计数与成本表](token-counter-and-cost-meter/)

拟定里程碑：

1. 构建关联来源的事实与约束账本
2. 创建有界抽取式上下文快照
3. 检查保留情况和自编矛盾案例
4. 提交或恢复上下文并保留审计回执

**范围边界：** 基线验证明确结构化约束和自编词汇关系。可选模型摘要需要独立评估，不能把这些检查说成一般语义等价证明。

<a id="local-inference-capacity-planner"></a>

### 本地推理容量规划器

帮助团队为自己的模型端点选择并发上限。重放自编到达计划，分开记录队列等待与服务时间，在有界运行间比较观察到的分位数和超时。根据实测请求导出容量曲线和可编辑运行限制，而不是查模型名表。

**独立重点：** 本地模型评估框架为输出评分；本项目在受控到达计划和并发下测量队列行为。

**首先构建的演示：** 用三个并发上限重放相同自编到达计划，比较队列等待与服务延迟。

**语言：** Python, Go

**交付物：** 负载重放清单、容量曲线和实测运行限制回执

**基于：** [本地模型评估框架](local-model-eval-harness/)、[agent 预算规划器](agent-budget-planner/)

拟定里程碑：

1. 定义到达计划和资源上限
2. 独立测量队列与服务时间
3. 在相同工作负载上比较并发设置
4. 导出可复现容量决定

<a id="mcp-protocol-compatibility-doctor"></a>

### MCP 兼容性诊断器

帮助集成作者诊断已连接却无法正确使用服务器的客户端。通过有界传输 adapter 运行自编协商、请求关联与能力探测。导出兼容矩阵和解释失败的最小线协议记录，移除凭据。

**独立重点：** MCP 工具发现工作台教授提供与发现工具清单；本项目诊断独立实现的客户端和服务器间的分歧。

**首先构建的演示：** 连接两个能力声明不一致的自编本地参与者，导出首个失败交换。

**语言：** TypeScript, Python

**交付物：** 协议探测 CLI、兼容性 JSON 和脱敏复现记录

**基于：** [MCP 工具发现工作台](mcp-at-scale/)、[agent 追踪调试器](agent-trace-debugger/)

拟定里程碑：

1. 记录初始化与协商能力
2. 探测支持的操作和请求关联
3. 将失败交换缩减为必要消息
4. 导出客户端／服务器兼容性回执

**范围边界：** 实现时固定所选 MCP 规范修订版和传输；按该版本验证探测，明确报告不支持能力。规划探测不是通用一致性认证。

主要参考：[参考 1](https://modelcontextprotocol.io/specification/2025-11-25/basic/lifecycle)。

<a id="metamorphic-evaluation-workbench"></a>

### 蜕变评估工作台

帮助评估者发现相关输入间的不一致行为。编写单位转换、记录重排和等价格式等变换，定义各变换应保留的输出关系，缩减违规示例。导出基于性质的评估运行器和 CI 可消费的小型失败包。

**独立重点：** prompt 回归测试器比较不同 prompt 版本的已知案例；本项目生成相关输入，检查输出的领域不变量。

**首先构建的演示：** 重排自编表格，改变等价单位记法，定位违反答案契约的变换。

**语言：** Python, TypeScript

**交付物：** 变换／性质运行器、最小化反例 JSON 和 CI 结果

**基于：** [prompt 回归测试器](prompt-regression-tester/)、[JSON Schema 输出守卫](json-schema-output-guard/)

拟定里程碑：

1. 定义输入变换与预期关系
2. 运行成对案例并记录响应来源
3. 检查关系并缩减违规案例
4. 导出可复现性质失败

**范围边界：** 这些关系是对特定任务编写的假设。通过不代表一般模型质量；随机 adapter 必须保留重复运行证据。

<a id="oauth-resource-boundary-lab"></a>

### OAuth 资源边界实验

帮助开发者集成委托授权，不接受发给其他服务的 token。构建本地授权和资源 fixture，执行元数据发现，将授权绑定到请求资源，在服务器检查 audience 与 scope。导出可复用校验中间件及拒绝请求的脱敏解释。

**独立重点：** 工具调用防火墙检查拟议工具动作；本项目确定委托凭据实际授权了哪个资源和哪些权限。

**首先构建的演示：** 用本地签发的 token 访问两个虚构资源，解释第二个为何拒绝。

**语言：** Go, TypeScript

**交付物：** 本地授权 fixture、资源服务器中间件和授权决定记录

**基于：** [MCP 工具发现工作台](mcp-at-scale/)、[工具调用防火墙](tool-call-firewall/)

拟定里程碑：

1. 建模客户端、签发者和资源身份
2. 发现元数据并绑定 proof-key 授权流程
3. 拒绝错误 audience 和不足 scope
4. 集成中间件并导出脱敏决定

**范围边界：** 编码前固定 MCP 授权修订版及底层 OAuth 要求。默认用本地签发者，独立验证任何外部身份提供者 adapter；不要将 OAuth 2.1 草案说成最终 RFC。

主要参考：[参考 1](https://modelcontextprotocol.io/specification/2025-11-25/basic/authorization)、[参考 2](https://www.rfc-editor.org/info/rfc8707/)。

<a id="outbound-request-policy-proxy"></a>

### 出站请求策略代理

帮助开发者限制按不可信文档 URL 取回内容的工具。评估 scheme、主机、解析地址和每次重定向，在明确大小与时间限制内连接已校验目标。导出本地出站 adapter 及揭示重定向与地址策略错误的 loopback 案例。

**独立重点：** 带回退的 LLM 网关选择已配置 provider；本项目限制任意 URL 取回操作的网络目标，包括重定向转换。

**首先构建的演示：** 跟随最终目标违反地址策略的自编本地重定向链，检查被阻止的一跳。

**语言：** Go

**交付物：** 带策略的 HTTP adapter、目标决定回执和对抗本地 fixture

**基于：** [带回退的 LLM 网关](llm-gateway-with-fallbacks/)、[工具调用防火墙](tool-call-firewall/)

拟定里程碑：

1. 解析目标并定义地址策略
2. 将解析决定绑定到实际连接
3. 重新校验重定向并限制响应
4. 导出 adapter 并重放拒绝请求

**范围边界：** 记录支持的 DNS、代理和网络假设。进程级 adapter 不是操作系统沙箱，也不保证绕过它的流量行为。

<a id="release-canary-decision-lab"></a>

### 发布金丝雀决策实验

帮助团队判断 agent 行为变更是否可扩大开放。分配稳定请求分组，比较候选与基线错误、延迟窗口，区分证据不足和门禁失败。导出可重放决定回执及本地影子 adapter，不部署任何东西也能演练策略。

**独立重点：** Harness Bench 在固定数据集比较策略；本项目研究序贯发布决定、分组分配和随时间积累的证据。

**首先构建的演示：** 重放自编基线与候选请求，经过先证据不足、再触发明确停止决定的窗口。

**语言：** Python, Go

**交付物：** 金丝雀策略运行器、本地影子 adapter 和停止／继续／证据不足回执

**基于：** [Harness Bench](harness-bench/)、[agent 追踪调试器](agent-trace-debugger/)

拟定里程碑：

1. 分配稳定分组并定义发布信号
2. 积累可比较的基线和候选窗口
3. 应用最小样本与停止规则
4. 通过本地影子 adapter 重放决定

**范围边界：** 只导出建议。声明所选统计假设，不把小型通过窗口解读为通用发布安全。

<a id="secret-injection-sidecar"></a>

### 密钥注入 sidecar

帮助开发者将服务凭据排除在模型可见工具参数和常规追踪之外。构建本地 broker，解析不透明句柄，将句柄绑定到目标和操作，在网络边界插入环境提供的凭据。测试回显凭据标记，导出有界响应过滤后的决定回执。

**独立重点：** 工具调用防火墙授权动作；本项目从 agent 接口移除原始凭据，测试 broker 的可观察边界。

**首先构建的演示：** 用不透明句柄调用本地 fixture，展示返回追踪中不含其原样回显的凭据标记。

**语言：** Rust, Python

**交付物：** 本地凭据 broker、基于句柄的客户端 adapter 和脱敏请求回执

**基于：** [工具调用防火墙](tool-call-firewall/)、[Rust 流式 agent shell](rust-agent-shell/)

拟定里程碑：

1. 定义不透明句柄和目标绑定授权
2. 在 broker 边界内注入凭据
3. 演练响应与追踪脱敏 fixture
4. 集成仅使用句柄的客户端

**范围边界：** 使用环境密钥和 loopback 测试服务。精确标记过滤只展示有界性质，不能保证任意上游服务绝不泄露变换后的密钥。

<a id="tenant-fairness-scheduler"></a>

### 租户公平调度器

帮助平台开发者在任务大小不同的租户间共享有限 worker 池。实现加权赤字调度、有界准入和老化，在自编突发负载下比较各租户等待分布。导出队列 adapter 和工作负载回执，让饥饿与闲置容量可见。

**独立重点：** agent 预算规划器核算调用者提供的用量和截止时间；本项目决定谁得到下一执行槽并测量公平性。

**首先构建的演示：** 重放一个虚构租户的突发请求，同时另一租户提交小任务，在两种队列策略下比较等待。

**语言：** Rust, Python

**交付物：** 公平队列 adapter、负载重放 CLI 和各租户等待／吞吐报告

**基于：** [持久 agent 作业](durable-agent-jobs/)、[agent 预算规划器](agent-budget-planner/)

拟定里程碑：

1. 表示租户队列和声明任务成本
2. 实现加权赤字调度
3. 限制准入并检测饥饿
4. 在重放突发负载上比较公平性

**范围边界：** 相对于声明或实测服务单位定义公平性，暴露成本估计误差。本地 adapter 不声称提供分布式共识。

**独立重点：** 持久 agent 作业协调队列租约；本项目研究任务持有多个稀缺资源又请求其他资源时的循环等待。

**首先构建的演示：** 重放两个本地 agent 以相反顺序获取浏览器和工作区，再展示能完成的调度。

拟定里程碑：

4. 导出协调器和可重放死锁证据

**范围边界：** 有界探索器只能证明实际检查的调度。明确定义资源语义，区分死锁、慢任务、饥饿和崩溃后的资源占用。

<a id="trajectory-counterexample-minimizer"></a>

### 轨迹反例最小化器

帮助 agent 开发者诊断依赖动作顺序的失败。表达批准必须先于效果等有界时序规则，检查事件追踪，在保留声明因果依赖的同时删除无关事件。导出包含违规规则和精确事件标识的最小重放包。

**独立重点：** agent 追踪调试器解释执行时间；本项目检查事件顺序性质，自动缩减失败轨迹。

**首先构建的演示：** 将二十事件的自编运行缩减为复现过期批准违规所需的批准与效果事件。

**语言：** Rust, Python

**交付物：** 时序追踪检查器、保留依赖的缩减器和最小重放包

拟定里程碑：

1. 规范化事件与声明因果依赖
2. 检查有界时序规则
3. 不破坏前置条件地最小化失败
4. 导出最小可复现违规

**范围边界：** 因果保留依赖已记录依赖和支持的规则语言。最小追踪是相对于所选缩减器和重放判定器而言，不是全局最小性证明。

<a id="transactional-workspace-patch-broker"></a>

### 事务工作区补丁 broker

帮助并发编码 agent 避免多文件变更进行一半时互相覆盖。将补丁包绑定到内容哈希，在私有版本化工作区应用，运行声明检查，再通过切换一个工作区指针发布。导出事务 API、冲突证据和明确回滚日志。

**独立重点：** 微型编码 agent 教授编码循环；本项目在多个 agent 提出重叠多文件修改时，让发布和冲突变得明确。

**首先构建的演示：** 让两个本地 worker 提出重叠修改，展示一个完整发布和另一个的版本冲突。

**语言：** Rust, TypeScript

**交付物：** 工作区事务 API、可评审补丁包和冲突／回滚日志

**基于：** [微型编码 agent](tiny-coding-agent/)、[沙箱策略规划器](sandbox-ladder/)

拟定里程碑：

1. 将多文件补丁绑定到输入版本
2. 在私有版本化工作区暂存修改
3. 拒绝冲突并运行声明验证
4. 发布工作区指针并记录回滚

**范围边界：** 原子性适用于版本化工作区指针及遵守它的读取者。不要宣称对现有检出任意写入多个文件是原子的。
