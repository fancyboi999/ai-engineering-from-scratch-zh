# 读取显式日历区间

**类型：** Build
**语言：** TypeScript
**阶段：** 第 1 阶段，共 4 阶段
**预计时间：** 约 2 小时，需先完成链接中的前置内容
**前置要求：** [开发环境](../../../../../phases/00-setup-and-tooling/01-dev-environment/docs/zh.md)、[数据管理](../../../../../phases/00-setup-and-tooling/09-data-management/docs/zh.md)。

## 构建内容

本阶段推进日历专注计划器：找到日历中的真实空闲时间，安排优先任务，并解释哪些任务放不下。

公开契约为 `parseCalendar(text)`。随附 CLI 和样本文件位于你的工作区；在 `main.ts` 中实现领域函数。保留签名，使其他应用也能调用同一边界。

## 推演机制

日历文本是一种协议，不是松散的日期列表。读取属性前先展开续行。把每个事件的身份、摘要、开始和结束保存在一起。拒绝缺失或倒置的端点和重复身份。已取消或透明事件不应占用专注时间。

这个有界解析器接受具有明确 `DTSTART` 和 `DTEND` 的 UTC 时间戳和纯日期事件。全天 `20261014` 事件需要不含结束日的 `DTEND;VALUE=DATE:20261015`；不要推断省略的结束值，也不要用 `DURATION` 替代。它拒绝重复和时区规则，因为悄悄将其当作一个 UTC 事件会制造虚假的空闲时间。事件使用半开区间：结束点是第一个不再被占用的时刻。

| 事件 | 开始 | 结束 |
|---|---|---|
| 团队同步 | 09:30 | 10:15 |
| 答疑时间 | 10:00 | 11:00 |
| 工作坊 | 13:00 | 14:30 |

## 扩展

导入全天事件，解释为什么白天不再有空档。

范围：解析器支持显式 UTC 事件和全天日期。重复规则和命名时区必须先由日历导出器展开，遇到它们会拒绝。CLI 规划 UTC 09:00–17:00 的一天。它只创建本地建议，从不修改账号日历。

主要参考：[iCalendar RFC 5545](https://www.rfc-editor.org/rfc/rfc5545)。实现和练习数据均为原创教学示例。
