课后实作。现有一个冻结的视觉编码器（单图输出 197 个 768 维 token）和一个冻结的文本嵌入表（嵌入维度 512）。请构建能够让二者实现模态对齐通信的最小网络模块，在图文对齐配对样本上完成训练，并交付证明其正常生效的测试用例集。请描述架构设计、损失函数、训练流程以及测试用例。

## Short answer

将 197 个图像 token 池化为单一向量，送入中间带 GELU 激活层的两层 MLP（维度 768 到 1024 到 512），再用余弦对齐损失（1 减去余弦相似度）与均值池化后的文本描述嵌入对齐。在冻结视觉编码器和文本嵌入表的前提下，仅针对该 MLP（约 1.3M 参数量）使用几十对图文样本训练几百步。验证测试包括：投影层输出维度严格等于文本嵌入维度、冻结模块无可训练参数、余弦损失在相同向量时为 0 且在反向向量时为 2、单步反向传播后梯度成功传导至投影层权重，以及最后一步的损失低于第一步。

## Full answer

### 架构设计

```text
image tokens (B, 197, 768) -> pool -> (B, 768)
MLP: Linear(768, 1024) -> GELU -> Linear(1024, 512) -> (B, 512)
caption ids -> frozen table -> mean over tokens -> (B, 512)
loss = 1 - cos(image_emb, text_emb)
```

池化策略：取第一个 token 是最简单的选择；对剩余 196 个 patch token 取均值是另一种有效备选，课程练习对比了两者。采用两层是因为单一线性映射无法弯曲空间；GELU 提供了对齐两个基底所需的一次弯折。

### 参数量核算

| 网络层 | 权重形状 | 参数量计算 |
|---|---|---|
| 第一层 Linear | 768 × 1024 | 768 × 1024 + 1024 |
| GELU | 无 | 0 |
| 第二层 Linear | 1024 × 512 | 1024 × 512 + 512 |

总计约 1.3M 参数量，而视觉编码器本身有 86M 参数。两个大模块的所有参数均显式标记 `requires_grad=False`。

### 训练主循环

- 不允许使用数据集时，按随机种子合成 32 对样本，并循环使用。
- 优化器只绑定投影层自身的参数。
- 运行 200 步，每隔 25 步打印一次当前损失。项目实测损失值从约 1.07 降至约 0.80。
- 训练结束打印各对样本的最终余弦相似度。

### 交付的五大单元测试

1. 投影层输出张量的形状严格匹配配置的输出宽度。
2. 冻结的文本表和冻结的视觉编码器参数中，要求梯度的参数数量为 0。
3. 余弦损失函数在两个完全相同的向量输入时严格输出 0，在反向平行向量时严格输出 2。
4. 经过单次反向传播后，梯度确实成功传递回投影层的权重张量。
5. 训练第 200 步的损失严格小于第 0 步的初始损失。

### 最终交付产物

投影层的权重文件是唯一的全新交付产物。在推理时，视觉编码器先执行前向提取，接着由投影层将其投射至大语言模型的嵌入向量空间中。所有开放适配器模型都呈现出相同的模式：池化、投影、独立对齐。

### 延伸讨论的下一步演进

单对余弦损失只拉近了正样本的方向；对比损失（Contrastive loss）还能进一步推开批次内的其他负样本图文对。对于需要让每个词精准感知局部的复杂解码器，可用基于文本 Query 的交叉注意力直接去读取 197 个 patch token，替代这里的单一池化向量；这正是后续实战项目的内容。

## Follow-ups

- **Level 2:** 为什么选用余弦相似度损失，而不选用均方误差（MSE）？ Expected: 特征对齐衡量的是在联合表征空间中的方向一致性，而非向量数值绝对相等；余弦具有尺度不变性，投影层不会因为文本嵌入模长恰好偏大而受到惩罚。
- **Level 2:** 在余弦损失中加入可学习的温度系数（temperature）会改变什么？ Expected: 改变损失曲面的平缓或陡峭程度；温度太小会导致梯度噪声过大，太大则过早陷入高位平缓平台，正如实验所示。
- **Level 3:** 实测中 200 步后损失停在 0.80 附近，这是物理底限吗？ Expected: 不是，这只是某次训练在 200 步时的损失；投影层拥有 1024 个隐单元而样本仅 32 对，更多步数或调优学习率可以把损失压得更低，而在真实自然图像上则取决于编码器特征本身的表征上限。
- **Level 3:** 该模块与基于 Query 的桥接层（Q-Former）有何联系？ Expected: 桥接层最终同样以类似的线性投影映射至文本维度；核心差异在于桥接层先用可学习 Query 做交叉注意力压缩，而非简单的几何池化。

## Wrong answers

- "把视觉编码器一起微调，它才 86M 参数。" 大作业明确要求冻结底座是有原因的：几十对样本根本无法训练编码器，且检查文本表是否冻结的测试会失败。
- "使用单层线性层即可，旋转空间足够了。" 两个基底的差别不只是旋转；非线性让一次弯折能够弥合差距。
- "跳过单元测试，反正训练损失已经下降了。" 损失下降完全可能是张量形状 Bug 或梯度泄露到冻结底座造成的假象；测试锁死的是损失函数本身无法证明的系统契约。
