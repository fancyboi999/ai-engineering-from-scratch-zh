## 缓存为什么能得到相同结果

在因果解码器中，第 $t$ 步只关注第 0 到第 $t$ 步。这些时间步的 key 和 value 不会因新 token 到来而改变，因此缓存只需存储一次。使用缓存计算第 $t$ 步的输出，等于完整因果注意力的第 $t$ 行。比较两者是验证缓存实现的主要方法。

## 为什么使用固定容量

服务引擎会在处理请求前分配缓存内存。它不会在每个时间步扩展数组，因为反复复制大型缓存会很慢。因此缓存有固定的 `max_len`，超出容量的追加操作会报错。写入前先检查，可使报错后的缓存仍然有效。

## 缓存的内存开销

每一层会为每个 token、每个 key/value 头保存一个 key 和一个 value。内存用量为 $2 \times N \times \text{layers} \times \text{heads}_{kv} \times d_{head} \times \text{bytes}$。上下文较长时，缓存占用的内存往往超过权重。分组查询注意力通过减少 key/value 头的数量来降低这项开销。

同一课程还会介绍维护运行最大值的分块注意力。它每次处理一块 key，计算出相同的 softmax。分页缓存将固定数组拆成多个块，让多个请求共享同一个内存池。
